# 设计说明

本文记录需要跨模块对齐的设计决策。参数标注「待定」的项需要在硬件确定后补全。

## 1. Flash 分区

采用 A/B 双区，Boot 区不参与升级，保证升级失败仍能进入引导。

| 区域 | 起始地址 | 大小 | 说明 |
|---|---|---|---|
| Bootloader | `0x08000000` | 32 KB | 含向量表，永不覆盖 |
| 分区表 | `0x08008000` | 1 KB | 记录当前有效分区、版本、CRC |
| App A | `0x08008400` | 待定 | 运行分区之一 |
| App B | 待定 | 待定 | 升级分区 |
| 参数区 | 末页起 | 2 KB | 标定值与故障码，升级不清除 |

分区大小待 STM32 型号确定后按 `(Flash 总容量 − Boot − 分区表 − 参数区) / 2` 计算。

### 1.1 参数区布局

参数区切成两页，交替写入。布局固定，跨版本、跨工具链读取：

```
页 0                           页 1
┌──────────────────────┐      ┌──────────────────────┐
│ magic  "NVMS"   4 B  │      │ ...                  │
│ seq             4 B  │      │                      │
│ len             2 B  │      │                      │
│ crc32(payload)  4 B  │      │                      │
│ 保留            2 B  │      │                      │
├──────────────────────┤      ├──────────────────────┤
│ payload       ≤1008 B│      │                      │
└──────────────────────┘      └──────────────────────┘
```

payload 再分两层：

```
ver(1) param_len(2) params(param_len) dtc_len(2) dtc_blob(dtc_len)
```

- `params` 目前只有 4 字节：DID `0x0201` 的标定值。向后追加字段只需增大 `param_len`，
  旧数据仍可读（读不到的字段保留默认值）
- `dtc_blob` 由 `dtc_export` 生成：版本(1) + 操作循环号(4) + 条数(2) + 每条 46 字节

**参数区必须独立于 `uds_memory_t`**：刷写流程会擦除 App 分区，参数区若与它共用
接口，「升级把标定值一起擦掉」这类错误很难在设计评审时发现。

### 1.2 为什么用双页而不是原地覆盖

擦除本身是不可中断的破坏动作。单页方案在擦到一半掉电时，参数与 CRC 一起失效，
设备只能回默认值——对 ECU 来说等于标定丢失、故障历史清零。

双页方案下，任何时刻至少有一页完整：

```
保存前：  [A: seq=7 有效] [B: seq=6 旧]
擦 B、写 B（掉电在此）→ A 仍有效
写完回读校验通过 → B 生效，seq=8
```

`seq` 用于判断哪页更新。比较时用有符号差值而非直接比大小，
否则回绕之后（`0xFFFFFFFF` → `0`）会一直读到回绕前的那一页。

### 1.3 写入时机

| 触发 | 处理 |
|---|---|
| `0x2E` 写标定值 | 立即落盘。回了正响应就必须真的存下来 |
| 故障状态变化 | 由主循环每秒检查一次，状态签名变化才写 |
| 正常退出 | 强制落盘一次 |

不按「内容是否变化」逐字节判断的原因：故障的 status 位每 10ms 就变一次
（本循环测过没、本次失败没），逐字节比较会让`一天写两万次`成为常态。
判断依据取「值得留存的部分」：操作循环号、条数、每条码的 pending/confirmed/warning
位、发生次数、老化进度。

同时保留 2 秒的最小写入间隔，参数连续写入时不会连擦两页。

## 2. 升级流程

```
上电 → 读分区表 → 校验有效分区 CRC
                    ├─ 通过 → 跳转 App
                    └─ 失败 → 等待 UDS 编程会话
```

写入侧：

1. tester 进入扩展会话 → `0x27` 解锁 → 进入编程会话
2. `0x31` 擦除目标分区（非运行分区）
3. `0x34` 请求下载 → `0x36` 连续传输 → `0x37` 退出传输
4. `0x31` 校验 CRC
5. 写分区表，`0x11` 复位

**关键约束**：升级区永远是「非运行分区」。运行区被擦除等于变砖，这是双区存在的唯一理由。

## 3. 跳转条件

跳转前必须三项都通过，任一失败留在 Boot 等待诊断：

- 栈顶值落在 SRAM 范围内（`0x2000_0000` – `0x2002_0000`，具体上限看型号）
- 复位向量落在目标分区范围内
- 分区 CRC-32 与分区表记录一致

跳转动作：关中断 → 设 `MSP` 为 App 栈顶 → 取 Reset_Handler 地址 → `BX`。

## 4. UDS 会话状态机

```
默认会话 ──0x10 02──→ 编程会话 ──0x10 01──→ 默认会话
   │                      ↑
   └──0x10 03──→ 扩展会话 ─┘
                    │
                    └─ S3 超时（5 s）→ 回默认会话
```

- 除 `0x10` / `0x3E` 外，其他服务在默认会话下返回 NRC `0x7F`（服务不支持于当前会话）
- 编程会话下禁止应用报文收发，避免升级期间总线干扰
- 安全访问未解锁时，`0x2E` / `0x31` 返回 NRC `0x33`（安全访问拒绝）

## 5. 错误处理

| 事件 | 处理 |
|---|---|
| 发送错误，TEC +8 | 不立即干预，由硬件计数累积 |
| TEC > 127 | 进入错误被动，上报 `err_level = 1` |
| TEC > 255 | 进入 Bus Off，上报 `err_level = 2` 并记录 `busoff_cnt` |
| Bus Off 恢复 | 硬件完成 128×11 隐性位后自动恢复，软件只做计数与上报 |

软件不实现「自动重连」逻辑——CAN 控制器的 Bus Off 恢复由硬件负责，
软件层重复实现只会掩盖真实的物理层故障。
