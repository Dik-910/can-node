# 通信协议

> 状态：**草案 v0.1**。三方共用（can-node / bms-node / smartgateway），
> 任一侧修改报文定义必须同步更新本文件并提升版本号。

## 1. ID 分配

采用 11 位标准帧。按功能域分段，避免不同节点争用同一 ID：

| 区间 | 用途 | 说明 |
|---|---|---|
| `0x100` – `0x17F` | 节点状态 | 心跳、错误计数、版本 |
| `0x180` – `0x1FF` | 实时数据 | 采样值、周期上报 |
| `0x200` – `0x27F` | 控制命令 | 网关下发 |
| `0x280` – `0x2FF` | 事件与故障 | 故障码、状态迁移 |
| `0x7DF` | 诊断功能寻址 | 广播请求 |
| `0x7E0` – `0x7E7` | 诊断物理请求 | tester → ECU |
| `0x7E8` – `0x7EF` | 诊断物理响应 | ECU → tester |

约束：

- 同一 ID 只允许一个发送方，多节点需要同数据时由发送方广播。
- 周期报文抖动控制在 ±10% 内。
- 诊断报文不设周期，按需触发。

## 2. 报文定义

### 2.1 节点状态 `0x180`

发送方：can-node。周期 100 ms。DLC = 8。

| 起始位 | 长度 | 信号 | 类型 | 说明 |
|---|---|---|---|---|
| 0 | 8 | `node_state` | uint8 | 0 初始化 / 1 正常 / 2 降级 / 3 故障 |
| 8 | 8 | `err_level` | uint8 | 0 主动 / 1 被动 / 2 BusOff |
| 16 | 16 | `busoff_cnt` | uint16 | 累计 Bus Off 次数，小端 |
| 32 | 32 | `uptime_s` | uint32 | 上电秒数，小端 |

### 2.2 总线状态 `0x181`

发送方：can-node。周期 20 ms。DLC = 8。

| 起始位 | 长度 | 信号 | 类型 | 说明 |
|---|---|---|---|---|
| 0 | 8 | `tec` | uint8 | 发送错误计数，0–255 |
| 8 | 8 | `rec` | uint8 | 接收错误计数，0–255 |
| 16 | 16 | `bus_load_pm` | uint16 | 总线负载率，千分比 |

> TEC 在 Bus Off 判据中需要超过 255，单字节装不下。本表按饱和值 255 上报，
> 真实的超限由 UDS `0x22` 按 DID 读取 2 字节原始值。

### 2.3 采样数据 `0x200`

发送方：bms-node。周期 50 ms。DLC = 8。

| 起始位 | 长度 | 信号 | 类型 | 因子 / 偏移 | 单位 |
|---|---|---|---|---|---|
| 0 | 16 | `pack_voltage` | uint16 | ×0.01 | V |
| 16 | 16 | `pack_current` | int16 | ×0.01，充电为正 | A |
| 32 | 8 | `soc` | uint8 | ×1 | % |
| 40 | 8 | `temp_max` | int8 | ×1，偏移 −40 | ℃ |
| 48 | 8 | `prot_state` | uint8 | 0 正常 / 1 告警 / 2 保护 / 3 恢复 | — |
| 56 | 8 | `fault_code` | uint8 | 当前最高优先级故障码，0 表示无 | — |

### 2.4 控制命令 `0x300`

发送方：网关。事件触发，非周期。DLC = 4。

| 起始位 | 长度 | 信号 | 类型 | 说明 |
|---|---|---|---|---|
| 0 | 8 | `cmd` | uint8 | 1 启动 / 2 停止 / 3 清故障 |
| 8 | 8 | `seq` | uint8 | 序列号，回滚重发用 |
| 16 | 16 | `param` | uint16 | 命令参数，保留 |

> 带 `seq` 是因为 CAN 无重传机制，网关需要判断命令是否被接收方处理过。
> 节点在 `0x180` 的 `node_state` 里回报最近处理的 `seq`。

### 2.5 故障事件 `0x280`

发送方：bms-node。事件触发，非周期。DLC = 8。

| 起始位 | 长度 | 信号 | 类型 | 说明 |
|---|---|---|---|---|
| 0 | 16 | `fault_code` | uint16 | 故障编号 |
| 16 | 8 | `fault_level` | uint8 | 0 提示 / 1 告警 / 2 保护 / 3 严重 |
| 24 | 8 | `occur_count` | uint8 | 同一故障累计出现次数，饱和 255 |
| 32 | 32 | `event_time_s` | uint32 | 相对上电的秒数，小端 |

> 故障事件只在状态迁移时发送，不做周期重复。网关丢失单帧时，
> 靠下一次 `0x200` 里的 `fault_code` 字段恢复当前状态。

## 3. 字节序

- 多字节信号统一**小端**（Intel 格式），与 Cortex-M 原生一致，避免转换开销。
- 例外：UDS 诊断报文内的多字节参数按 ISO 14229 规定使用**大端**。

## 4. UDS 寻址

| 场景 | 请求 ID | 响应 ID |
|---|---|---|
| 物理寻址 | `0x7E0` | `0x7E8` |
| 功能寻址 | `0x7DF` | 多节点响应，需错开延时 |

ISO-TP 参数：

- 标准地址格式，单帧最大 7 字节
- 连续帧间隔 STmin 默认 10 ms
- 块大小 BS = 0，即不分块流控

## 6. 机器可读定义

本文件的表格与 [`can_matrix.dbc`](can_matrix.dbc) 一一对应，**以 DBC 为准**。
DBC 已通过 `cantools` 加载与编解码往返验证，可直接用于：

```bash
pip install cantools
python -c "import cantools; db=cantools.database.load_file('docs/can_matrix.dbc'); print(db.messages)"
```

网关端与节点端都应从同一个 DBC 生成解析代码，不要各自手写字节偏移。
